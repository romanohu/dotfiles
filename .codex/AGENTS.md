## Implementation Guidelines

- Prefer the smallest change that fully solves the current task.
- Minimize the Git diff. Change only the files and lines necessary to complete the task.
- Preserve existing structure, naming, formatting, and style unless changing them is required for correctness.
- Do not perform unrelated cleanup, reformatting, renaming, or refactoring.
- Do not add features, abstractions, configuration, compatibility layers, or generalizations unless they are required now.
- Reuse existing patterns and infrastructure before introducing new ones.
- Avoid speculative handling for hypothetical future requirements.
- Keep changes focused; do not refactor unrelated code unless necessary for correctness.
- Apply these guidelines silently. Do not mention or restate them in responses unless they materially affect a design decision.
